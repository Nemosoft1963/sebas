# 改修依頼: 実装単位2Cの残課題修正(テスト2件の失敗を直す)

## 背景
単位2C(workflow確定ゲートへの接続)は、これまでのセッションでほぼ実装済み。
`pytest -q` で **479 passed, 2 failed, 1 skipped**。この2件の失敗だけを直してほしい。
`app/context_files.py` の `extraction_quality` 関数は今回の作業と無関係なので、調査・変更しないこと。

## 失敗1: test_workbook_has_source_and_allocation_sheets

```
tests/test_vehicle_integration.py:81: AttributeError: 'str' object has no attribute 'value'
statuses={row[11].value for row in wb['原本照合'].iter_rows(min_row=2, values_only=True) if row[0]}
```

原因: `iter_rows(..., values_only=True)` は既にセルの値そのもの(文字列等)を返すため、
`row[11].value` ではなく `row[11]` が正しい。**このテストの該当行を `row[11].value` から
`row[11]` に修正するだけでよい**(実装コード側のバグではなく、テストの誤り)。

## 失敗2: test_auto_extract_without_independent_total_cannot_pass_source_controls

```
tests/test_vehicle_integration.py:97:
assert not (not data.get('auto_extraction',{}).get('issues') and not data.get('source_controls'))
AssertionError: assert not (not [] and not [])
```

原因: このテストは「`auto_extraction.issues` と `source_controls` が両方とも空なら不合格」という
**旧い実装(単位2A/2B以前)の判定方法**をそのままアサートしている。単位2Cでは、
不合格判定は `source_reconciliation_report()` が返す `summary`(`passed`/`matched`/`mismatched`/
`unavailable` 件数)で行うよう変更済み。このテストの該当行(97行目)を、
`summary['passed'] is not True`(既にテスト内で確認済みの`summary`変数を使う)や
`summary.get('unavailable', 0) > 0` など、**新しい `source_reconciliation_report` の戻り値を使う
形に書き換える**こと。テストの意図(「独立合計が無い場合は確定できない」)は変えずに、
判定方法だけを単位2Cの新しいAPIに合わせる。

## やること
1. 上記2件のテストの該当箇所だけを修正する。
2. `pytest -q`(プロジェクト全体)を実行し、**480 passed, 0 failed**(または妥当な件数)になることを確認する。
3. `extraction_quality` には一切触れない。
