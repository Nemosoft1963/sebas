### 項目1. 認証・認可がない

**再確認（現行も正しい）**

- `app/web.py` に `Depends`・ログイン・セッションCookie・CSRF・Origin 検査はない。
- コンテナ内 uvicorn は `0.0.0.0:8000`（`docker/Dockerfile` CMD）。ホスト公開は `docker-compose.yml` の `127.0.0.1:8099:8000`（open-webui/cptr/qdrant/google-browser も同様）。
- `SYSTEM_DESCRIPTION_FOR_AI.md` §1.2 は「複数組織・多数ユーザー向けの認証／認可基盤」を非目的と明記。§10.3 は localhost が主防御と明記。
- トークン型の公開入口 `/premarketing/{token}` はキャンペーン捕捉用。LAN に出せばリード情報が届く。

**深刻度:** セキュリティ（高）— ただし「製品を SaaS にする」話ではない。誤ってポートを `0.0.0.0` にした瞬間に、プロジェクト資料・Workspace 操作・外部アクション承認が無認証で届く。

**対応方針（採用）:** フルRBAC・利用者分離は **今はやらない**。やることは「localhost 境界を壊れにくくする」こと。

**概略（この順）**

1. **製品判断の確認（実装前、人間）**  
   LAN/VPN 公開が要件なら、アプリ内ログインより **認証付き reverse proxy + TLS** を先に検討（文書 §10.3 と同じ）。要件が localhost のままなら 2. へ。
2. **バインド不変条件のテスト化**  
   - `tests/` に compose の ports がすべて `127.0.0.1:` で始まることの静的テストを追加。  
   - 対象: `docker-compose.yml`（web / open-webui / cptr / google-publisher-browser / qdrant）。  
   - `0.0.0.0` やホスト省略を検出したら失敗。
3. **運用ドキュメントの一文強化**  
   `SECURITY.md` / `README.md` に「ポート公開を 127.0.0.1 以外へ変えない。変えるなら reverse proxy」を既存節へ追記。新規の認証基盤の章は作らない。
4. **任意の薄い共有トークン（要件が出たときだけ）**  
   環境変数例: `LOCAL_COWORK_API_TOKEN`（空なら現行どおり無認証＝localhost前提）。  
   空でないときだけ、変更系 HTTP（POST/PUT/DELETE）と WebSocket に `Authorization: Bearer` またはヘッダを要求。  
   **GET の静的 HTML と `/premarketing/{token}` は別判断**（公開LPはトークン自体が鍵）。  
   Cookie セッションを導入すると CSRF が必要になるので、**Cookie は使わない**。

**触るファイル（2. までなら）**

- 新規: `tests/test_localhost_binds.py`
- 文書: `SECURITY.md`、必要なら `README.md` / `SYSTEM_DESCRIPTION_FOR_AI.md` §10.3（内容は既にあるので重複を避ける）

**トークンを入れる場合に触るファイル**

- `app/web.py`（ミドルウェアまたは依存関数。巨大ファイルなので **新規 `app/local_access.py` を作り web から呼ぶ**）
- `docker-compose.yml` / `.env.example`（変数名のみ、値は空）
- フロント `app/static/*.js`（fetch / WebSocket にヘッダ）
- テスト: トークン空＝全通、トークンあり＝無しは 401

**やってはいけないこと**

- ユーザーDB、パスワードハッシュ、OAuth、RBAC をこのフェーズで始めない。
- 8099 を `0.0.0.0` にしない。
- Open WebUI / Computer の認証（各自の初回管理者）と Integrated Front を混同しない。

**完了条件**

- compose の localhost バインドをテストが固定している。
- トークンを入れた場合: 既存 pytest がトークン空で従来どおり通る。

### 項目2. `app/web.py` への責務集中（2917行）

**再確認（現行も正しい）**

- 実測 2917 行、約 140KB。FastAPI ルート、SMTP、Google/Canva/SNS/LP、Workspace、WebSocket、音声、実行モニター、車両損益、目標レビューが同居。

- 関数内ローカル import が多い（`get_project_mission`、車両、goal-review など）。
- グローバル: `memory`, `llm`, `orchestrator`, `workspace`, `OLLAMA_MODEL`, `engine_enabled`, `executions`。

**深刻度:** 保守性（高）。セキュリティバグそのものではない。触ると全機能に波及する。

**対応方針:** **最初に分割しない。** フェーズ0〜2と項目1/8の安全化が終わってから。分割は挙動を変えない移動のみ。

**推奨分割単位（1 PR = 1 領域）**

| 順 | 切り出す塊 | おおよその内容 | 新規モジュール案 |
|---|---|---|---|
| A | 実行モニター | `executions` / `start_execution` / `/api/monitor` | `app/execution_monitor.py` |
| B | 外部アクション・SMTP | `ALLOWED_EXTERNAL_ACTIONS`、`_send_approved_email`、`/actions*` | `app/external_actions.py` |
| C | 静的ファイル配信 | `/static/*` の FileResponse 群 | `app/static_routes.py` または既存のまま |
| D | Workspace / context-files | 一覧・操作・upload・会計プレビュー | `app/workspace_api.py` |
| E | プレマーケティング一式 | campaigns〜google/social/creative/landing | `app/premarketing_api.py`（最大・最後から2番目） |
| F | 車両損益 API | `/vehicle-profit*` | `app/vehicle_api.py` |
| G | 目標レビュー API | `/goal-review*` | `app/goal_review_api.py`（後半は1行圧縮スタイル） |
| H | 組み立て | `FastAPI(...)`、lifespan、install 呼び出し | `app/web.py` に残すか `app/app_factory.py` |

**手順（各 PR 共通）**

1. 対象ルートの既存テストを列挙し、分割前に `pytest` で対象＋全件を記録。
2. 関数を **カット＆ペースト相当** で移す。シグネチャ・HTTP パス・ステータス・メッセージを変えない。
3. グローバル参照は引数または小さな `AppEnv` プロトコル（`memory`/`llm`/`workspace` 等）にまとめる。`sys.modules[__name__]` は残してよい（既存 install との互換）。
4. `app/web.py` の改行は CRLF 混在がある（`docs/CHANGELOG_2026-09-21_none_and_default.md`）。**ファイル全体の write は禁止。** `edit_file` またはバイト差替。
5. 一括整形（1行圧縮の展開）は **しない**。差分が追えない。

**検証:** 分割領域のテスト ＋ `python -m pytest tests -q` 全件。パス一覧が `/docs` 相当で変わらないこと（TestClient でルート名をスナップショットするテストを先に追加すると安全）。

**壊れやすい点:** lifespan の install 順、`engine_enabled`、`select_local_model` の `global OLLAMA_MODEL`、プレマーケティングの公開トークンページ。
