# LocalSAPORTER フォールバックPDF読取スキル 接続要求・詳細指標

- 文書日: 2026-09-24
- 文書種別: 実装要求仕様・受入基準・実験結果
- 対象システム: LocalSAPORTER / Local Cowork
- 対象機能: PDF通常抽出が不足・文字化け・表崩れした場合のローカルOCRフォールバック
- 候補エンジン: PaddleOCR-VL-1.6（0.9B）+ PP-DocLayoutV3
- 状態: 接続前。単体実験は成功、本番統合は未実施

## 1. 目的

LocalSAPORTERへ登録されたPDFについて、現在の`pypdf`文字抽出で十分な根拠を得られない場合だけ、ローカルOCRを自動起動する。抽出結果には原本・ページ・領域座標を結び付け、計算処理が「読めなかった」を「0円・取引なし」と誤判定しないようにする。

本機能は次を達成する。

1. 通常PDF抽出を優先し、不要なGPU処理を抑える。
2. 画像PDF、文字化けPDF、複雑な表をOCRで補完する。
3. 金額、日付、車両番号、数量、単価、税、請求、入金を区別して構造化する。
4. OCRの推測値を確定値として扱わず、検算と人間確認を通す。
5. 人間が承認した結果だけを経験RAGへ再利用可能にする。

## 2. 現状と不足機能

### 2.1 現在利用できる機能

- `app/context_files.py`
  - PDF原本を`pypdf`で最大500ページまで抽出する。
  - `readable`、`garbled`、`unreadable`を判定する。
  - 一部の文字化けについて可逆復元候補を原抽出と分離して保持する。
  - 抽出結果を最大200,000文字へ制限する。
- `app/capability_registry.py`
  - `source.extract_pdf_text`を登録済み。
  - 「OCR・一般的な表復元は保証しない」と明記済み。
  - `source.extract_table`は登録されているが、現在は`unavailable / unsupported_operation`。
- コンテキストファイル保存
  - 原本バイト列、SHA-256、MIME、ファイル種別、抽出注記を保持できる。

### 2.2 不足している機能

- OCR実行能力が機能レジストリにない。
- PDF品質判定からOCRを自動起動するルーターがない。
- OCRのページ・領域・値単位の証跡スキーマがない。
- OCR結果と通常抽出結果を比較する検算ゲートがない。
- 表を業務項目へマッピングする帳票アダプターがない。
- UIで原本、領域、抽出値、訂正値を並べて承認できない。
- 承認結果をRAGへ登録する前の証跡検査がない。
- GPUサービスの起動、排他、停止、タイムアウト、再試行制御がない。

## 3. スキル定義

### 3.1 能力ID

| 能力ID | 役割 | 初期状態 |
|---|---|---|
| `source.ocr_pdf_fallback` | PDFをページ画像化し、レイアウト分割後にOCRする | 新規登録 |
| `source.extract_pdf_table` | OCR結果から表セルと行列構造を返す | 新規登録 |
| `source.validate_ocr` | 合計、日付、表、反復、通常抽出との整合を検査する | 新規登録 |
| `source.review_ocr` | UIで根拠画像と抽出値を人間確認する | 新規登録 |
| `source.publish_approved_ocr` | 承認済み結果だけを後続計算とRAGへ公開する | 新規登録 |

`source.extract_table`の既存IDは互換性を考慮し、`source.extract_pdf_table`の別名として移行できる。能力チェックは「設定済み」と「実行検証済み」を分離し、Dockerイメージがあるだけで`validated=true`にしない。

### 3.2 入力契約

必須入力:

| 項目 | 型 | 条件 |
|---|---|---|
| `project_id` | string | LocalSAPORTERプロジェクトID |
| `context_file_id` | string | 登録済み原本ID |
| `filename` | string | `.pdf`のみ。正規化済み相対名 |
| `original_sha256` | 64桁hex | 保存済み原本と完全一致 |
| `original_data` | bytes | DBに保持された原本。外部URL参照は禁止 |
| `page_count` | integer | 1以上500以下。超過時は範囲選択へ送る |
| `purpose` | enum | `context`, `table`, `accounting`, `vehicle_profit`, `evidence` |
| `requested_fields` | array | 金額、日付、車両番号等。未指定なら全文・表抽出 |

任意入力:

- 対象ページ範囲
- 帳票種別候補
- 既知の会社、車両、勘定科目マスター
- 通常抽出本文と品質判定
- 期待する合計式
- 業務ルール版と回答済み確認事項ID

必須成果物:

1. `ocr_result.json`: 機械処理用の完全結果

4. `page-N.png`: OCRに入力したページ画像
5. `validation.json`: 検算結果と停止理由
6. `manifest.json`: 全成果物のSHA-256、サイズ、生成日時

## 4. フォールバック起動条件

通常抽出後、次のいずれかを満たすページだけOCRへ送る。

| 指標ID | 起動条件 | 初期閾値 |
|---|---|---:|
| TRG-01 | `extraction_quality == unreadable` | 即時起動 |
| TRG-02 | `extraction_quality == garbled` | 即時起動 |
| TRG-03 | 置換文字・制御文字率 | 0.5%以上 |
| TRG-04 | 文字密度 | 1ページ50文字未満 |
| TRG-05 | PDFが画像中心 | ページ面積の80%以上が画像 |
| TRG-06 | 依頼が表抽出で、通常抽出に行列構造がない | 起動 |
| TRG-07 | 金額候補はあるが項目名と対応できない | 起動 |
| TRG-08 | 通常抽出と既知合計が不一致 | 1円以上の差 |
| TRG-09 | ユーザーが原本照合を指定 | 起動 |

正常に読める文字PDFはOCRを`skipped`にし、理由を記録する。OCRを全PDFへ常時適用しない。

## 5. 処理フロー

1. 原本SHA-256を再計算し、DB記録と一致しなければ停止する。
2. `pypdf`通常抽出と品質指標を計算する。
3. OCR起動条件をページ単位で判定する。
4. 対象ページを200〜300DPIのPNGへ変換する。
5. PP-DocLayoutV3でレイアウトを検出する。
6. 各領域をPaddleOCR-VL-1.6で認識する。
7. JSON、Markdown、領域画像を保存する。
8. 通常抽出との一致、金額式、明細合計、日付、反復を検査する。
9. 帳票アダプターが業務項目へ割り当てる。
10. 合格なら`passed`、曖昧なら`needs_review`、実行不能なら`failed`とする。
11. UIへ原本・領域・抽出値・検算を提示する。
12. 人間承認後だけ後続計算へ公開する。
13. 人間がRAG再利用を指定した場合だけ、承認結果と証跡を経験RAGへ登録する。

## 6. 業務項目の分離要件

会計・車両損益では、次の値を別フィールドとして保持する。

- 前月請求額
- 当月入金額
- 差引繰越額
- 当月買上額
- 当月請求額
- 税額
- 値引・調整額
- 購入日
- 支払日・入金日
- 車両番号
- 商品
- 数量
- 単価
- 明細金額
- レシート番号

前月請求、支払、入金を当月費用へ自動配賦してはならない。車両番号が存在しない入金行は車両原価明細に変換しない。

## 7. 検算・停止条件

### 7.1 自動検算

| 指標ID | 検査 | 合格基準 |
|---|---|---|
| VAL-01 | 原本同一性 | 保存SHA-256と再計算値が完全一致 |
| VAL-02 | ページ網羅 | 対象ページ処理率100% |
| VAL-03 | 領域追跡 | 全抽出値にpage、block_id、bboxあり |
| VAL-04 | 金額形式 | Decimalへ損失なく変換可能 |
| VAL-05 | 明細合計 | 許容差0円。税丸め規則がある場合のみ規則値 |
| VAL-06 | 請求式 | 前月残、入金、当月買上、請求の式が帳票と整合 |
| VAL-07 | 反復検出 | 同一短文の連続反復10回未満 |
| VAL-08 | 文字化け | 置換文字・制御文字率0.5%未満 |
| VAL-09 | 車両番号 | 車両原価へ使う行は車両マスター一致またはレビュー済み |
| VAL-10 | 日付 | 対象月と取引日・締日の役割を区別できる |
| VAL-11 | 二重計上 | 同一原本SHA、ページ、行キーの重複0件 |
| VAL-12 | 空値意味 | 空欄、0、読取不能を別状態で保持 |

### 7.2 強制停止条件

次は`needs_review`または`failed`とし、後続計算へ渡さない。

- 原本ハッシュ不一致
- OCRサービス停止またはタイムアウト
- ページ欠落
- 同じ文字列の異常反復
- 金額の合計不一致
- 当月額と前月額・入金額の区別不能
- 車両番号が必要な明細で番号不明
- OCR結果しか根拠がなく、重要金額が単独認識
- JSONスキーマ違反
- 成果物ハッシュ不一致

`failed`や`needs_review`を0円へ変換しない。「ファイルなし」と「ファイルあり・読取不能」を同一扱いしない。

### 8.4 可用性・復旧

| 指標ID | 指標 | 基準 |
|---|---|---|
| OPS-01 | ヘルスチェック | OCR要求前に`/health`が200 |
| OPS-02 | 起動失敗 | 通常抽出結果を保持し、OCR失敗として記録 |
| OPS-03 | 再開 | 原本SHAとページ単位チェックポイントから再開 |
| OPS-04 | 冪等性 | 同一原本・モデル・パラメータは同一実行キー |
| OPS-05 | 停止 | アイドル後にGPUサービス停止可能 |
| OPS-06 | ロールバック | OCR能力を無効化して従来抽出へ戻せる |

## 9. セキュリティ・プライバシー

1. 原本とOCR画像を外部AI、外部OCR API、公開Webへ送らない。
2. Docker公開ポートは`127.0.0.1`のみとする。
3. Cドライブ全体、Users全体、Docker socketをマウントしない。
4. 原本は対象ファイル単位の読取専用マウントを優先する。
5. 成果物はプロジェクト配下へ限定し、パストラバーサルを拒否する。
6. ログへ原本全文や個人情報を常時出力しない。
7. モデル、イメージ、設定のdigestを監査記録へ残す。
8. モデル更新時は受入データセットを再実行し、旧版と比較する。

### 10.2 永続化

既存DBへ追加型マイグレーションで次のテーブルを加える。

- `ocr_runs`
  - run_id、project_id、context_file_id、source_sha256、status、trigger、engine、version、parameters_hash、started_at、finished_at、elapsed_ms、error_code
- `ocr_pages`
  - run_id、page_no、image_sha256、width、height、status
- `ocr_blocks`
  - run_id、page_no、block_id、label、bbox_json、text、confidence

原本BLOBを複製しない。`context_file_id`と`source_sha256`で参照する。

## 11. UI要求

プロジェクトのファイル一覧に次を表示する。

- 通常抽出品質: 読取可能、文字化け、読取不能
- OCR状態: 未実行、キュー、処理中、要確認、承認、失敗
- 起動理由
- ページ数、処理済みページ数
- 処理時間、モデル版
- 「OCRで再読取」操作

レビュー画面は左右比較とする。

- 左: 原本ページ。選択値のbboxを強調表示
- 右: 抽出Markdown、構造化項目、検算結果
- 訂正欄: OCR値、訂正値、訂正理由
- 操作: 承認、訂正して承認、却下、再実行
- RAG操作: 「この承認結果を再利用知識へ登録」。既定は未選択

「OCR成功」と「業務計算への採用済み」を別表示にする。

## 12. エラーコード

| コード | 意味 | 後続動作 |
|---|---|---|
| `OCR_NOT_REQUIRED` | 通常抽出で十分 | OCRをスキップ |
| `OCR_SERVICE_UNAVAILABLE` | ローカルサービス未起動 | 再試行または要確認 |
| `OCR_TIMEOUT` | 制限時間超過 | 要確認 |
| `OCR_SOURCE_HASH_MISMATCH` | 原本不一致 | 強制停止 |
| `OCR_PAGE_RENDER_FAILED` | ページ画像化失敗 | 強制停止 |
| `OCR_LAYOUT_FAILED` | レイアウト検出失敗 | 要確認 |
| `OCR_REPETITION_DETECTED` | 異常反復 | 結果不採用 |
| `OCR_SCHEMA_INVALID` | 出力スキーマ不正 | 結果不採用 |
| `OCR_TOTAL_MISMATCH` | 合計不一致 | 後続計算停止 |
| `OCR_FIELD_AMBIGUOUS` | 項目の意味不明 | 人間確認 |
| `OCR_ARTIFACT_TAMPERED` | 成果物ハッシュ不一致 | 強制停止 |
| `OCR_REVIEW_REQUIRED` | 重要値の確認待ち | 公開禁止 |

## 13. 実験結果

### 13.1 対象

- ファイル: `燃料/202605/ENEOS20260531‗サンプル物流.pdf`
- ページ数: 1
- ファイルサイズ: 102,137 bytes

6. OCRサービス停止時も既存システムが壊れず、失敗理由を表示できる。
7. 人間承認前のRAG登録0件。

## 17. 判定

PaddleOCR-VL-1.6とPP-DocLayoutV3の組合せは、LocalSAPORTERのフォールバックPDF読取スキルとして接続可能である。採用対象はレイアウト分割を含む構成に限定する。全ページ直接VLM入力は禁止する。

現時点の判定は「技術試行合格・本番接続未完了」。次の開発着手点はPhase 1のスキーマ、OCRクライアント、機能レジストリ、証跡manifestである。
