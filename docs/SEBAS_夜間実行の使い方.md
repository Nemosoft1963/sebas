# SEBAS 夜間実行の使い方（C-3「人が起動する夜間実行」）

人が「今夜これを回して」と起動すると、すでに人が自走を有効にしたPJだけを、
決められた時間枠・予算・回路遮断の内側で、既存の自走ティックを順番に回し、
朝に実行報告を残す。夜間実行が自走を有効にすることはない。
常駐しない（アプリ内に定期スレッド・スケジューラ・タイマーを作らない）。
通知は画面内だけ。

## 前提

- 夜間実行に任せる前に、自走を有効にするPJと理由を確認する。
- 有効化は人の判断（PJごとの自走設定画面）。夜間実行は有効化しない。
- 実案件のPJのデータには、テストで書込まない（疑似PJのみ）。

## 起動のしかた

```sh
python scripts/night_run.py --actor 山田 --until 05:00 --max-ticks 60 --per-project 5
```

- `--actor` は必須（開始者名）。
- `--until HH:MM` は必須（終了時刻。当夜の時刻。過ぎた時刻は翌日扱い）。
- `--max-ticks` は総ティック数（既定60）。
- `--per-project` はPJあたりのティック数（既定5、上限10）。
- `--base-url` はローカルのセバスAPI（既定 `http://127.0.0.1:8099`）。
  ローカルホスト以外は拒否する。
- `--dry-run` は何も書かず、回す予定のPJと理由だけを表示する。

終了コードは、正常終了=0、中止/失敗=非0。

## 止め方

- Ctrl+C：中断して finish を呼んで終わる。
- `POST /api/autopilot/disable-all`（担当者名必須）：全PJの自走を無効化し、
  同時にキルスイッチを有効にする。画面の「夜間実行」パネルの
  「全PJの自走を止める」ボタンからも実行できる（確認ダイアログあり）。
- キルスイッチの解除は人が `POST /api/autopilot/kill-switch/release`
  （担当者名必須）でのみ行う。

## 朝の見方

- 画面の「夜間実行」パネル：最新の実行の状態・時間・ティック数・中止の原因・
  PJごとの結果・人の次の操作、キルスイッチの状態。
- 見張りの通知：実行ごとに `night_run_finished` / `night_run_aborted` が1件
  作られる（全体イベント。冪等キー=run_id）。
- `GET /api/night-run/latest`：報告つき（読み取り専用）。

## 予算の目安

- 総ティック数：60（既定）。上限1000。
- PJあたり：5（既定）。上限10（既存の最大10ティックを超えない）。
- 時間枠：`--until` と最大実行秒数（既定6時間、上限12時間）。
- 連続失敗：3（既定）。事前照合の連続失敗：3（既定）。
- 1つでも超えたら止まる。

## 回路遮断

- いずれかのティックで外部増分（`external_delta` / `external_rounds_delta`）
  または予算維持の破れ（`budget_kept` が偽）があれば、直ちに夜間実行全体を
  中止する。該当PJの自走は既存の仕組みで無効化される。
- 事前照合の失敗（`preflight_unknown` / `stale` / `failed`）が連続で
  閾値に達したら中止する。
- 読み取り不能・不明な結果は成功扱いにしない（そのPJをその夜は除外し、
  失敗として数える）。
- 同じ停止の繰り返しは既存の空転ガードに任せ、PJごとに「進まない」ことが
  確定したら以後その夜は回さない。

## やってはいけないこと

- 夜間実行に任せる前に、自走を有効にするPJと理由を確認せずに起動すること。
- 夜間実行で承認・外部送信・Jenkins送信・適用・RAG登録・OCR投入・完全削除を
  自動化すること（夜間実行でも自動化しない）。
- Windowsのタスクスケジューラへの登録は実装しない（登録は人の判断）。
- 外部ホストのAPIに向けてランナーを動かすこと（ローカルホスト以外は拒否）。
