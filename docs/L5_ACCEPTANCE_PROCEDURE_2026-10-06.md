## 1. 疑似PJで検証済みの範囲

- 通し(正常系、1件): 許可(preview→start)→Gemini草案→ローカル整理→構造検査→
  第1回検証(不合格・安全な差分あり)→取り込み→修正案→未承認草案へ反映→新署名→
  第2回検証(合格)→人の計画承認待ちで停止。以下を示す。
  ①検証ちょうど2回 ②Gemini草案1回 ③計画承認・実行開始・RAG登録・外部公開が0件
  (mission状態は planning/ready/paused のまま、承認記録の件数不変、
  completion_gate未達、pending_ledgerで承認済みに見えない)
  ④外部呼出数が上限 `1+2×検証AI数+最大2` (検証AI1件で5)以下
  ⑤各ステップの担当(local/gemini)と元の判定・指摘が不変の記録として残る
  (第1回の指摘原文・provider・対象署名、第2回の新署名への追従)。
- 失敗注入(パラメタ化を含む): 各経路で安全に停止し、成功と表示しない。
  provider未選択 / 送信未承認(許可外AI・未接続) / 秘密混入(公開用説明への混入は送信前に停止。
  Gemini草案の目標・達成条件・制約・工程説明・能力要約の各フィールドに
  APIキー様・認証ヘッダー・パスワード語+値・カード番号様・個人番号・語付き電話番号を仕込んでも停止) /
  計画版が途中で変わる / 接続障害(計画指摘に変換しない、stop_kind=connection_settings) /
  利用枠・予算不足 / 期限切れ / 未解決・追加開発(人の確認待ちで停止) /
  第2回も不合格(3回目は起きない) / Gemini草案の構造不正 / Gemini応答の指示混入 /
  ローカル整理の失敗(構造検査で検証前に停止) / Gemini整理の判定pass書換・指摘削除・指示混入 /
  全件対応の検査失敗。各ケースで停止理由が保存・取得できること、
  外部へ送られたpayloadに秘密値・原本本文・ファイル名が含まれないことを検査する。
- 停止→再起動→再開: 接続障害で停止したランで、再起動(同一DBへ新しいManagerで接続)後も
  Gemini草案・整理済み状態・第1回検証の記録・停止理由が残り、再開または取消を選べること。
  再開で外部呼出カウンタが増えない(送信済みpacketの無断再送なし)。
  同じ開始要求の再送でGemini草案・外部検証・計画版が重複しない(冪等)。
  同時start(asyncio.gather)で二重に走らない(単一lease)。
  lease期限切れ後は新規開始が可能になる(復帰)。
  全段階(Gemini草案後/第1回検証後/取り込み後/反映後/第2回検証後)の保存内容は、
  正常系通しの記録と再起動試験の記録で確認する(各段階の保存項目が残ることの実測)。
- 既存の安全機構との整合: L4の反映が既存の `review_plan` / `propose` /
  `validate_candidate` / `apply` / P1-C修復ラン / pending_ledger / completion_gate を
  迂回していないこと(呼び出し回数の計測で review_plan=2、validate≧1、apply=1を確認)。
  反映後に旧評価が失効し(新署名で再評価待ち)、反映後の独立検査
  (元の達成条件と必要成果物が全て残る・未解決指摘がない・新署名で再評価待ち)が
  失敗すれば旧版を保持しロールバック可能な差分(対応表・旧revision)が残る。
  GoalContract hashが変わらないこと。弱める差分(具体的な差分の不足)は反映せず停止し旧版を保持する。
  P1-C修復ランは別経路として残り、L4が勝手にpassedにしない。
- 読み取り専用の確認: preview・状態取得(GET)・一覧が、呼び出し前後で
  DB・承認・実行記録・外部送信カウンタを変化させない。previewは外部送信を行わない(API経由を含む)。
- 秘密検出の精度(横断): `compile_plan` / `compile_task` で組み立てた疑似実運用計画
  (uuid hexのID、日付、SC番号、金額、ファイルパスを含む)が誤検出で止まらず通しを完走できること。
- ソケット非開放の検証を含む(外部送信の実通信なし。`_post_json_uncached` を監視し呼出0件)。

## 3. 実案件で受入を行う場合の手順

前提: 起動前に必ずバックアップを取る。docker-compose*.yml と docker/proxy/ は変更しない。

1. バックアップ: conversations.db 本体と goal_reviews.sqlite3、goal_completion.sqlite3、
   experience_memory/、workspace を退避する。
2. 最初に呼ぶ読み取り専用APIの順序(書き込みをしない):
   auto-loop の preview → 状態取得・一覧(GET)。**auto-loop の preview は外部送信しない**。
   結果の送信範囲・指摘・停止理由・次操作を記録する。
3. 外部送信を許可する前の確認事項: 送信される公開用要約の内容を人が読むこと、
   送信先AI、最大呼出数(`1+2×検証AI数+最大2`)、期限。
   **外部AIへ実際に送信されるのは、利用者が明示許可(start)したあと**であること。
4. 許可してはならない条件: 秘密・個人情報を含む可能性がある計画、
   検証AIが1つもない運用、Geminiのみの自己評価
   (独立した検証を要する運用では少なくとも1つ別のAIを指定する)。
5. 中止方法(cancel): 実行中のループは cancel で取り消す。
   変な書き込み・承認・実行が起きたら直ちに中止し、退避したDB・索引・成果物へ戻す。
   差分が app/ に及んだ場合は捨てる(L5の成果は tests/ と docs/ の追加差分だけとして扱う)。

## 4. 既知の限界(正直な記載)

- 秘密検出は**パターンベースで網羅的ではない**。未知の形式の秘密、文脈依存の機微情報、
  自然文で書かれた個人情報や社内機密は検出できない。
  **最終的な送信可否は人が公開用要約を読んで判断する**。
- 区切りも語もない10桁の数字列(電話番号等)は検出しない(uuid・工程番号との区別のため)。
- 確認者名は本人性を保証しない(認証は未実装)。
- 通信はTLSなし。
