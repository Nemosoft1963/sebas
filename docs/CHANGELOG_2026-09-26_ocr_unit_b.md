# OCR 実装単位 B 変更履歴（2026-09-26）

宇佐美御買上明細の、文字層で欠落した車番ブロックだけを、人間承認済み OCR で補完する。
失敗した OCR 実行は、新しい冪等キーのときだけ再実行できる。

## 抽出規則

OCR の `table` ブロック `text` は HTML 表として扱う。標準ライブラリ `html.parser` で
行(`tr`)×セル(`td`/`th`) に変換し、空セルを除いたセル列をページ内のブロック順・行順に走査する。
HTML 文字列へ正規表現を直接当てない。明細行の数量・単価・金額は使わない。

1. 明細行: 先頭2セルが4桁数字。2セル目が `plate4`。
2. 小計: セル `小計` の直後の数値セル。
3. 参考消費税: `参考消費税…` の直後の数値（括弧を除く。読めなければ無視。検算には含めない）。
4. 軽油引取税: `軽油引取税` を含む行の最後の数値セル。
5. 車番ラベル: `車番：…` の末尾4桁。
6. 印字合計: `品名` で始まる行で、セル `合計` の直後の数値。次行の別合計は使わない。
7. 区切り: `plate4` が変わると新ブロック。印字合計で閉じる。複数 table / ページにまたがってよい。
8. 検算: `小計 + 軽油引取税 == 印字合計`。不成立・欠落・非数値・車番不一致・同一車番の重複・低信頼は不採用。0円や推測で補わない。

計上金額は通常経路と同じ `小計 + 軽油引取税 + 参考消費税`。

## 採用条件

- 宇佐美補完に使うのは、人間レビューの `approve` / `correct_and_approve` 済み run だけ。
- `passed` だけでは使わない。`failed`・未承認・恒等式不成立は使わない。
- `Extractor.fuel` は、文字層で小計または印字合計が欠けたブロックにだけ OCR を使う。
- 通常抽出で両方の値が取れているブロックは上書きしない。
- 既存の請求書向け `is_ocr_adoptable` / `apply_ocr_adoption` は変えない。

## 再実行の規則

- 同一冪等キーの再送は既存実行を返す。
- `passed` / `needs_review` / 実行中があるときは、新しいキーでも既存を返す。
- 最新が `failed` で、新しい冪等キーなら、試行番号を parameters に付けて新規実行を作る。旧 run は残す。
- 同一ファイルの実行数が 5 に達したら拒否する。

## 維持した安全条件

- 読取失敗を 0 円にしない。推測しない。
- 前月請求・入金・繰越を当月費用に入れない。
- AI が承認を書かない。
- 人間承認前の後続計算・RAG 採用禁止は変更していない。

## 検証範囲

- 架空 HTML 表による US-01〜US-06 と RT-01。
- Docker、GPU、実OCRサービス、実PDFでの確認は実施しない。
