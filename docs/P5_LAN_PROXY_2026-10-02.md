# P5 認証付き LAN プロキシ（2026-10-03）

LAN 側の 8099 は nginx の限定 API だけを受け付ける。Web 本体は localhost で管理する。基底 `docker-compose.yml` も localhost のみにしたため、通常の Compose 起動で認証なし LAN 公開へ戻らない。

許可する API は `GET /api/health`、成功事例の取込、agent example の取込、general learning の GET/POST のみ。全許可パスに `X-Sebas-Token` が必要で、それ以外のパスは拒否する。プロキシ設定は Docker イメージに同梱し、ネットワークドライブの bind mount に依存しない。

切替には `scripts/enable_lan_proxy.ps1` を使用する。スクリプトは Compose を検証し、Web とプロキシだけを順番に更新する。`SEBAS_PROXY_TOKEN` はプロセス環境または `.env` から Compose が読み取る。値を画面やログへ出さない。

今回の本番設定では `SEBAS_ALLOWED_CLIENT=0.0.0.0/0` で、送信元 IP 制限は有効ではない。Docker Desktop の NAT を経由した 48G 実機の送信元アドレスを確認してから制限を追加する。通信は HTTP で TLS はないため、LAN 内でトークンを盗聴できる環境では別途 TLS が必要。

検証: LAN の health はトークンなし 401、正しいトークン 200、許可外パス 403、localhost の Web は 200。Web の実公開は 127.0.0.1 のみ。プロキシの実公開は指定 LAN アドレスのみ。48G 端末からの実送信は未検証。

ロールバック: 問題時はまずプロキシサービスだけを止め、Web は localhost のまま維持する。バックアップは `temp/p5_backup_20261002`。認証なしの LAN 直接公開へ自動で戻さない。復旧後に設定・テストを確認してプロキシを再起動する。Docker volume や OCR サービスを削除しない。
