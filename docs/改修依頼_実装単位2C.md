# 改修依頼: 実装単位2C(P0-2/P0-3 → workflow確定ゲートへの接続)

## 背景
単位2A(データモデル・純粋関数)・単位2B(アダプター接続)は実装済み・全体464件合格。
今回は最後の単位2C: `app/vehicle_workflow.py` の合格判定を、単位2A/2Bで作った
`reconcile_sources` の結果に接続する。`docs/対応設計_最終版_2026-09-23.md` 第2.3節に従う。

## やること

### 1. `validate_evidence()` の自動・手入力分岐を廃止
- 現行: `data['auto_extraction']` があれば `vehicle_auto.evidence_issues()` の結果だけを見て、
  通常入力用の `source_controls` 検査(167-177行付近)を通らない。
- 変更後: 自動・手動を問わず、共通の照合検査(`reconcile_sources` の結果)へ合流させる。
  そのうえで自動経路特有の `evidence_issues`(read_failure等)も追加でチェックする。

### 2. `checks['source_controls']` を空配列合格から卒業させる
- 設計書 第2.3節のJSON構造どおり、真偽値だけでなく詳細構造を保存する:
  ```json
  "checks": {
    "source_controls": false,
    "source_reconciliation": {
      "passed": false, "matched": 10, "mismatched": 1, "unavailable": 2,
      "artifact": ".../source_reconciliation.json"
    }
  }
  ```
- 合格条件:
  - 全対象sourceにdispositionがある
  - 必要なcontrolが`available`かつ`origin='source_total'`
  - reconciliationが全件`matched`
  - controlのない対象は`unavailable`として明示され、確定不可
  - read_failure、未根拠除外、重複control、`origin='sum_of_lines'`だけのcontrolは確定不可
- 互換用 `source_controls: bool` は、詳細チェックの `passed is True` からの導出に限り残す
  (空配列やissues空からのTrueは廃止)。
- `execute()` の `checks['source_controls']=not validate_evidence(...)` という代入は残してよいが、
  中身が空配列合格をやめる。
- `goal_failures()` は詳細チェックの `passed is True` のみを合格とする。

### 3. 暫定/確定の区別
- 暫定Excelは生成してよい(既存 `needs_review`)。
- 確定は `status='completed'` かつ全controlがmatchedのときのみ。

### 4. Excel照合シート(設計書 第2.4節)
- `app/vehicle_profit.py` の `build_workbook()` に照合結果を渡し、「原本照合」シートへ
  原本総額・取込・根拠付き除外・差額・未配賦・状態・原本位置・originを出す。
- 現在の「照合」シート(入力対配賦)とは分離し、名称を「配賦照合」に変更する。計算値自体は変えない。

## テスト
設計書 第2章「受入条件の検証方法」1〜9を `tests/test_vehicle_workflow.py` / `tests/test_vehicle_integration.py` に追加:
1. 原本統制額1000円、明細600+400 → matched、確定できる
2. 400円欠落 → mismatched、確定阻止(Excel再計算一致だけでは合格にしない)
3. 明細重複 → 差額または二重計上検出
4. 根拠付き除外100円 → matched。理由欠く除外は不合格
5. controlが取得不能 → unavailable、`checks['source_controls'] is True` にならない
6. 未配賦は原本対取込ではincludedだが、車両別確定ゲートでは阻害
7. source_ref/invoice_idが異なる統制値を混同しない
8. `origin='sum_of_lines'`だけのcontrolsでは合格にしない
9. 手動JSON経路の既存不一致試験を維持
