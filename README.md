# Local Cowork + Local Voice AI

Windows 11、Docker Desktop、Ollamaを使うローカル優先の作業AI環境です。従来の音声会話・プロジェクト別コンテキスト・複数外部AI調査を維持し、Open WebUIとOpen WebUI Computerを追加しています。

## 3つの画面

| 画面 | URL | 役割 |
|---|---|---|
| 統合フロント | http://127.0.0.1:8099 | ローカルLLM統制、音声入出力、共有コンテキスト、複数AI調査 |
| Open WebUI | http://127.0.0.1:3000 | ローカルモデル選択、チャット、Knowledge/RAG |
| Computer | http://127.0.0.1:8000 | Workspace、ファイル、Editor、Terminal、Git、Agent/MCP |

全ポートはlocalhostだけに公開します。Computerへ渡すホスト領域は、専用の `C:\LocalCowork\workspace` だけです。コードとUIはこの共有プロジェクトに残します。

## 構成

```text
統合フロント (8099)
  ├─ Local Ollama controller
  ├─ Voice input/output
  ├─ Project context / Markdown
  └─ Explicit external research
       ├─ Claude
       ├─ ChatGPT
       ├─ Gemini
       ├─ Grok
       └─ Meta

Open WebUI (3000) ─┐
Computer (8000) ───┴─ Windows Ollama (11434)
                         ├─ gpt-oss:20b
                         └─ qwen3.5:9b
```

外部AIは統合フロントの「外部AI 調査・資料作成」を明示実行した場合だけ利用します。通常会話と全体統制は `FRONT_AI_PROVIDER=ollama` のローカルLLMです。

## 初回セットアップ

PowerShell（実行ポリシー変更はこのプロセスだけ）:

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
```

続けて:

```powershell
Set-Location 'C:\LocalCowork\LOCALSAPORTER'
.\scripts\preflight.ps1
.\scripts\setup.ps1
.\scripts\pull-models.ps1
.\scripts\start.ps1 -BuildFront -Check
```

`pull-models.ps1` は大容量モデルを取得します。導入済みモデルは再利用されます。

## ローカルLLMの変更

統合フロント（http://127.0.0.1:8099）の「ローカルLLM」で、Ollamaへインストール済みの会話生成モデルを選択し、「このモデルに切替」を押します。

- 埋め込み専用モデルは候補に表示しません。
- 実行中の処理がある場合は、完了または停止するまで切替を拒否します。
- 稼働中は旧モデルを解放して新モデルを読み込み、失敗時は旧モデルへ戻します。
- 選択内容はデータボリュームへ保存され、Webコンテナ再起動後も保持されます。
- thinking非対応モデルでは高度思考指定を自動で無効化し、Ollamaの400エラーを防止します。
- この画面から未導入モデルのダウンロードは行いません。

従来のWindowsネイティブ音声コンソールは次で利用できます。

```powershell
.\scripts\start-console.ps1 -Voice
```

## 目標からの計画実行

Integrated Front（http://127.0.0.1:8099）でプロジェクトを選択し、次の順で操作します。

1. 「プロジェクト目標」「達成条件」「制約・注意事項」を入力して保存
2. 「AIで計画生成」でローカルLLMが草案を作成し、明示許可した複数AIが評価した後、ローカル統制LLMが最終計画へ高度化する
3. 計画を確認して「計画を承認」
4. 「実行開始」で依存関係を守り、独立タスクを設定した上限まで並列実行
5. 「中途報告・イベント」で進捗、成果、エラーを確認
6. 必要に応じて一時停止、再開、失敗タスクの再試行、中止
7. 完了後に「実行報告MD保存」で成果をダウンロード

目標、計画、タスク成果、中途報告、最終報告はSQLiteへ保存されます。同時に `__project_memory__/` 配下の目標・計画/手順・実行ログ・最終報告Markdownとして自動更新され、コンテキスト一覧から個別保存できます。実行中にアプリが再起動した場合は、安全のため一時停止状態へ復元されます。

「中途報告・イベント」には、逐語的な内部思考ではなく、利用者が監査できる判断要約を記録します。計画案の対象条件、採用モデル、提示・検証した原本数、実行操作数、能力不足、検証失敗理由、補正・差戻し理由を表示します。計画と実行のAI応答はJSON Schemaで構造を固定し、登録原本の参照証拠はバックエンドが実際に提示した原本IDから確定します。検証に合格しなかったAI生成ファイルは正式成果物から戻し、`.local_cowork_rejected/` へ回収して確認可能な状態で保持します。

完了状態と実タスクに矛盾がある場合は、起動時または完了検証時に自動で `paused` へ戻します。未完了タスクが残った状態でプロジェクト全体を完了扱いにはしません。

計画生成と通常タスクはローカルOllamaが統制します。「外部AIを計画評価・実現手段検討・調査タスクで利用する」を明示的に許可し、接続先を選んだ場合だけ外部APIを利用します。計画評価では目標・達成条件・制約・ローカル草案だけを送り、固定コンテキスト原本は送りません。各AIの評価はローカルLLMが統合し、外部AIを最終決定者にはしません。

## 公開Web調査の安全な指示

追加指示に「Webを検索して現行の公募要領を収集する」のように明記すると、HTTPSの公開ページを安全上限内で取得し、URL、取得日時、本文SHA256、抽出本文をプロジェクト原本へ保存します。補助金・法令・公募要領は発行主体の公式ページや公式PDFを優先し、公募回・版、対象、補助率・上限、期限、必要添付、申請経路、改訂情報を確認します。検索結果の要約やAI回答だけでは制度要件を確定しません。

「情報検索スキルを使う」「最新情報を取得」「公式サイト・公式PDFを確認」もWeb調査指示として認識します。計画内ではWeb調査を原本確認直後へ自動配置し、後続タスクから依存させます。試算表は財務分析・経営数値・ROI・補助申請額の算定タスクだけで必須とし、公募要領収集やシステム構成図を停止させません。Web調査は実際に取得メタデータ付き原本を保存できた場合だけ完了します。

同じ補助金・公募要領について複数回追加されたWeb調査指示は、要件を残したまま1工程へ統合します。検索サービスへはプロジェクト指示全文を渡さず、制度名と「最新・公募要領・公式・PDF」だけから作る公開用検索語を使用します。

公開Web調査工程の成果物は、ローカルLLMの自由形式出力に依存しません。バックエンドが取得済みWeb原本から、計画で要求された全見出し、原本ref、URL、取得日時、本文SHA256、公式候補状態を持つ監査レポートを決定論的に生成します。制度内容の解釈、事例、効果、構成図など取得原本だけで確定できない節は、捏造せず後続工程での確認対象として明記します。

検索語や外部AIには、試算表、社内資料、個人情報、認証情報を送りません。取得資料の整理・判断・成果物作成はローカルLLMを優先します。外部AIは利用許可がある場合でも、公開情報だけの助言・レビューに限定します。根拠URLを取得・検証できない重要事項は「要確認」とし、原本が必要な数値計画は最新試算表や見積書が登録されるまで確定しません。

同じ手順は `.codex/skills/public-web-evidence/SKILL.md` にスキルとして定義しています。


## 実現できない機能を発見した場合

タスク実行AIは、完了できない機能を `capability_gaps` として理由・必要能力・確認済み手段とともに報告します。外部AI利用を明示許可している場合は、選択済みで接続可能なAIへ目標、制約、対象タスク、不足内容だけを送り、実現方法・代替案・検証方法を並列評価させます。固定コンテキストと資料原本はこの評価には送りません。

外部AIの回答は命令として実行せず、ローカル統制LLMが採否と理由を判断して安全な再実行手順へ統合します。再設計後の実行は1回に限定し、それでも不足が残る場合はタスクを失敗として停止します。検出内容、外部AI評価状況、採用した手段、再実行結果、人間に必要な権限・接続・入力を「未解決事項レポート」としてUI、実行報告MD、`__project_memory__/90_final_report.md` に保存します。
## コンテキストフォルダ指定

「プロジェクトと共有コンテキスト」の「調査フォルダ追加」から、ローカルフォルダを選択できます。配下を再帰的に確認し、MDに限らず調査対象・参照データの原本を現在のプロジェクトへ登録します。登録名には選択フォルダ以下の相対パスが保持されます。

- 1回のフォルダ選択: 最大200ファイル
- 1ファイル原本: 最大10 MB
- プロジェクト全体: 原本100 MB、抽出本文2,000,000文字
- 本文抽出: MD/TXT/CSV/JSON/YAML/XML/HTML、主要なソースコード、PDF、DOCX/XLSX/PPTX
- 原本・目録保存: 画像、音声、動画、圧縮ファイル、その他バイナリ（本文抽出は未対応）
- AIへ渡す内容: 全ファイル目録と抽出本文。本文は要求ごとに最大60,000文字まで
- 一覧の「原本保存」からアップロード原本または自動生成メモをダウンロード可能
- フォルダを選び直すと同じファイルも追加登録されるため、不要な旧ファイルは一覧から削除する


## プロジェクト作業フォルダ

プロジェクト設定の「作業フォルダ（/workspace 内）」には、専用Workspace内の相対パスを設定できます。空欄の場合は `projects/<project-id>` を自動使用します。画面から一覧更新、フォルダ作成、UTF-8テキスト作成・更新、ファイル追加、ダウンロードができます。ローカル実行AIも同じ範囲を参照し、成果物を直接保存できます。

許可操作は `mkdir`、`write_text`、`append_text`、`copy`、`move` だけです。上書き前のファイルは `.local_cowork_backups/` へ自動退避され、パス脱出、symlinkによる範囲外アクセス、削除、任意シェル実行は拒否されます。

## 弥生会計Excelの内容確認

「プロジェクトと共有コンテキスト」の「ファイル追加」から、弥生会計で出力した仕訳データまたは試算表の `.xlsx` / `.xlsm` を登録できます。登録後の「内容確認」から、ブラウザ上で次を確認できます。

- 仕訳データ: 取引期間、仕訳行数、借方合計、貸方合計、貸借差額、勘定科目数、主要科目、セル明細
- 試算表: 貸借対照表・損益計算書などのシート別明細、行数、勘定科目行、合計行
- 弥生インポート形式: 見出しなしの標準列順（取引日付D、借方科目E、借方金額I、貸方科目K、貸方金額O）
- 一般Excel: 弥生形式を判定できない場合も、各シートのセル内容を表示

XLSMのマクロは実行しません。数式セルはファイルに保存済みの計算結果を表示します。展開後50 MB、1シート100,000行、表示100行の安全上限があります。旧形式 `.xls` は内容解析の対象外なので、弥生会計から `.xlsx` で出力してください。会計データはローカルで解析され、外部AIには送信されません。
## Computer初回設定

1. http://127.0.0.1:8000 を開く
2. コンテナログに表示される一回限りのsetup URL/tokenを使う
3. Workspaceとして `/workspace` を登録
4. AI接続先に `http://host.docker.internal:11434` を登録
5. OpenAI互換URLが必要な場合は `http://host.docker.internal:11434/v1` を使う

認証情報、Gateway key、パスワードは人間が画面で設定し、リポジトリへ保存しません。

## Workspace

- `C:\LocalCowork\workspace\inbox`: 入力原本
- `C:\LocalCowork\workspace\projects`: 作業中ファイル
- `C:\LocalCowork\workspace\knowledge`: 参照資料
- `C:\LocalCowork\workspace\output`: 完成成果物
- `C:\LocalCowork\workspace\temp`: 一時ファイル

詳しい運用は `OPERATIONS.md`、安全方針は `SECURITY.md`、検証結果は `BUILD_REPORT.md` を参照してください。

## Googleフォーム連携ランディングページ

公開済みGoogleフォームを問い合わせ先にしたLP資材を、キャンペーン単位で生成できます。プロジェクト画面の「LP資材生成」からHTMLプレビュー、Google Sites転記原稿、公開検証manifestを作成し、LP専用の申請・承認後に専用ブラウザでGoogle Sitesへ反映します。公開URLはシステムがタイトル、CTA、Googleフォーム導線を確認してから保存します。

Google Sitesのログイン、二要素認証、CAPTCHA、編集、公開操作は自動化しません。フォーム公開、LP公開、見込み客への連絡はそれぞれ別の人間承認を必要とします。
